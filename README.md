# Киноманьяк

## Задача и решение

Программа подбирает от одного до трёх фильмов из собственного каталога `films.json` по запросу на русском или казахском языке. Модель не должна придумывать название фильма или метаданные: она возвращает только `film_id` и короткую причину `why`. Код проверяет ID и сам печатает название, год, длительность и описание из каталога.

Без ML можно было бы искать фильмы по точным совпадениям слов в названии, жанре, языке и описании, а также фильтровать по году и длительности. Такой поиск хорошо работает для явно заданных полей, но плохо понимает смысловые запросы вроде «как Интерстеллар, но не про космос», синонимы, настроение фильма и сложные пожелания. Языковая модель помогает понять смысл запроса, а каталог и проверка ID ограничивают её выбор.

## Пять вопросов задачи

1. **Цель.** Подобрать подходящие фильмы под свободный запрос и показывать только записи из проверяемого каталога.
2. **Решение без ML.** Фильтровать по точным полям и ключевым словам. Минус: такой способ не понимает контекст и близость сюжетов, особенно если запрос сформулирован не словами из каталога.
3. **Данные.** `films.json`: 51 фильм, включая 13 казахстанских. Годы, длительности, страны и языки записаны по источникам; у каждой записи есть дополнительное поле `source`. Подробности и ссылки приведены в `README_films_sources.md`.
4. **Выход программы.** От нуля до трёх названий из каталога с годом, длительностью, жанрами, странами, языками, описанием и одной причиной `why`, сгенерированной моделью. При отсутствии подходящих записей программа сообщает `no_match`.
5. **Какова цена ошибки?** Если программа порекомендует неподходящий или несуществующий фильм, пользователь может потерять доверие к рекомендациям. Чтобы избежать выдуманных фильмов, программа проверяет каждый `film_id` по каталогу. Если ID отсутствует, ответ получает статус `invalid`, а фильм не показывается ([kino.py, строки 274–280](kino.py#L274-L280)). Также код проверяет повторы и корректность причины выбора ([kino.py, строки 282–292](kino.py#L282-L292)). Название, год, длительность и описание берутся непосредственно из каталога, а не из ответа модели ([kino.py, строки 294–305](kino.py#L294-L305)). При этом программа не может гарантировать, что существующий фильм действительно подходит по смыслу запроса.

## Установка

Нужны Python 3.12+ и `uv`. Создай локальный `.env` на основе примера:

```bash
cp .env.example .env
```

Заполни `OPENAI_API_KEY` и `OPENAI_MODEL`.

В корне проекта должен находиться `uv.lock`, добавленный в Git. Установи зависимости:

```bash
uv sync --frozen
```

Обычный запуск:

```bash
uv run kino.py "Фильм как Интерстеллар, но не про космос"
```

## Файлы проекта

- `kino.py` — загрузка каталога, промпт, Pydantic-схема, функция `pick()` и проверка результата.
- `films.json` — каталог из 51 фильма.
- `README_films_sources.md` — источники данных казахстанских и международных фильмов.
- `queries.json` — 15 разных запросов с ожиданиями `must`, `forbid` или `no_match`.
- `check.py` — прогон всех 15 запросов через выбранную модель.
- `show.py` — сводка по `calls.jsonl`: исходы, токены, цена и отклонённые ID.
- `memory_probe.py` — эксперимент с памятью модели без отправки каталоговых года и длительности.
- `tests/test_kino.py` — pytest-тесты с заглушкой, без API.
- `calls.jsonl` — журнал реальных вызовов модели.

## Проверки без API

Тесты используют локальную заглушку клиента и не обращаются к серверу:

```bash
uv run pytest -q
```

Проверяются следующие ситуации: чужой ID, повтор одного ID, `no_match`, успешная выдача и наличие тегов `<каталог>` и `<запрос>` в отправляемом сообщении.

Результат тестов:

```text
.....                                                                    [100%]
5 passed in 0.26s
```

## Локальная модель Qwen

Установи и запусти Ollama, затем скачай модель:

```bash
ollama pull qwen3.5:4b
```

В `.env` укажи:

```env
OPENAI_API_KEY=ollama
OPENAI_BASE_URL=http://127.0.0.1:11434/v1
OPENAI_MODEL=qwen3.5:4b
OPENAI_REASONING_EFFORT=none
```

`reasoning_effort="none"` передаётся в запрос, когда задан `OPENAI_REASONING_EFFORT`. Для Qwen это отключает рассуждения и делает пробный запуск на CPU существенно быстрее. После локального тестирования можно вернуть параметры облачного API.

## Эксперимент: память модели без каталога


## Проверка 15 запросов и журнал

Запуск:

```bash
uv run check.py
uv run show.py
```

`check.py` выполняет 15 реальных запросов и сверяет ответы с `expect`. Для каждого запроса с `must` должен быть выбран хотя бы один ожидаемый ID и не должно быть ID из `forbid`. Для `no_match` ожидается соответствующий исход. Все вызовы дописываются в `calls.jsonl`.

**Результат `check.py`:**

```text
no_match: 4
invalid: 0
Чужих ID поймано проверкой: 0
```

Все 15 запросов прошли проверку ожиданий.

## Источники данных

Для международной части использован `TMDb 5000 Movies Dataset` (`tmdb_5000_movies.csv`), а индивидуальная ссылка на карточку TMDb сохранена в `source`.

Для казахстанских фильмов использованы каталоги UCL, IFFR, Казахфильм и фестивальные каталоги. Полный список источников и правила преобразования находятся в `README_films_sources.md` и поле `source` каждой записи `films.json`.

Жанры, страны и языки приведены к русским названиям. Страна записана как `Казахстан`. `description` — краткий русскоязычный синопсис; это единственное поле, которое допускается формулировать с помощью модели.

## Ответы на вопросы по проверке

1. **Почему программа сверяет ID, хотя название понятнее? Сколько расхождений с каталогом дал эксперимент?**

   ID однозначно связывает ответ модели с конкретной записью каталога. Название может быть переведено, написано с ошибкой или совпасть у разных фильмов. Благодаря ID программа точно находит запись и выводит метаданные из каталога (`kino.py`, строки 274–305).

   В эксперименте с памятью модели обнаружено 4 расхождения по длительности из 10 фильмов. Ошибок в годах не было.

2. **Что произойдёт, если модель вернёт `film_id`, которого нет в каталоге?**

   `pick()` найдёт неизвестные ID, запишет их в поле `rejected`, вернёт `invalid` и пустой список ID. Пользователь не увидит такой фильм. Проверка находится в `kino.py`, строки 274–280. Повторы и пустой `why` отклоняются отдельно: строки 282–292.

3. **Чем «модель ответила без ошибки» отличается от «модель подобрала верный фильм»?**

   `ok` означает, что ответ разобран, ID принадлежат каталогу, нет повторов и выбрано не больше трёх фильмов (`kino.py`, строки 268–305). Это не доказывает смысловую правильность рекомендации. Её проверяют ожидания `must`, `forbid` и `no_match` в `check.py`, строки 55–76.

4. **Какое решение без ML и чего ему не хватает на запросах из `queries.json`?**

   Можно фильтровать по точным полям: году, длительности, языку и жанру, а также искать слова в названии и описании. Такой способ хуже понимает синонимы, перефразирование, настроение и сходство сюжетов. В текущей программе каталог вместе с запросом отправляется модели (`kino.py`, строки 180–207), а выбранные записи печатаются из локального каталога (`kino.py`, строки 294–305).

## Журнал и безопасность

`calls.jsonl` хранит время, модель, текст запроса вместе со списком ID каталога, исход и длительность вызова. При наличии данных `usage` сохраняются токены и расчётная стоимость. Сам каталог целиком в журнал не копируется.

API-ключ хранится только в `.env`. Файл исключён через `.gitignore` и не должен попадать в Git.
