# Киноманьяк

## Задача и решение

Программа подбирает от одного до трёх фильмов из собственного каталога `films.json` по запросу на русском или казахском языке. Модель не должна придумывать название фильма или метаданные: она возвращает только `film_id` и короткую причину `why`. Код проверяет ID и сам печатает название, год, длительность и описание из каталога.

Без ML можно было бы искать фильмы по точным совпадениям слов в названии, жанре, языке и описании, а также фильтровать по году и длительности. Такой поиск хорошо работает для явно заданных полей, но плохо понимает смысловые запросы вроде «как Интерстеллар, но не про космос», синонимы, настроение фильма и сложные пожелания. Языковая модель помогает понять смысл запроса, а каталог и проверка ID ограничивают её выбор.

## Пять вопросов задачи

1. **Цель.** Подобрать подходящие фильмы под свободный запрос и показывать только записи из проверяемого каталога.
2. **Решение без ML.** Фильтровать по точным полям и ключевым словам. Минус: такой способ не понимает контекст и близость сюжетов, особенно если запрос сформулирован не словами из каталога.
3. **Данные.** `films.json`: 51 фильм, включая 13 казахстанских. Годы, длительности, страны и языки записаны по источникам; у каждой записи есть дополнительное поле `source`. Подробности и ссылки приведены ниже и в `README_films_sources.md`.
4. **Выход программы.** От нуля до трёх названий из каталога с годом, длительностью, жанрами, странами, языками, описанием и одной причиной `why`, сгенерированной моделью. При отсутствии подходящих записей программа сообщает `no_match`.
5. **Цена ошибки.** Главная опасность — модель может вернуть несуществующий или неподходящий фильм. Чужой ID, повтор, более трёх фильмов и некорректная структура отклоняются. Ошибка отбора среди существующих ID всё ещё возможна, поэтому качество проверяется на `queries.json`.

## Установка

Нужны Python 3.12+ и `uv`. Создай локальный `.env` на основе примера:

```bash
cp .env.example .env
```

Заполни `OPENAI_API_KEY` и `OPENAI_MODEL`. Создай lock-файл и установи зависимости:

```bash
uv lock
uv sync --frozen
```

Добавь сгенерированный `uv.lock` в Git перед сдачей проекта.

Обычный запуск:

```bash
uv run kino.py "Фильм как Интерстеллар, но не про космос"
```

## Файлы проекта

- `kino.py` — загрузка каталога, промпт, Pydantic-схема, функция `pick()` и проверка результата.
- `films.json` — каталог из 51 фильма.
- `queries.json` — 15 разных запросов с ожиданиями `must`, `forbid` или `no_match`.
- `check.py` — прогон всех 15 запросов через выбранную модель.
- `show.py` — сводка по `calls.jsonl`: исходы, токены, цена и отклонённые ID.
- `memory_probe.py` — эксперимент с памятью модели без отправки каталоговых года и длительности.
- `tests/test_kino.py` — pytest-тесты с заглушкой, без API.
- `calls.jsonl` — журнал вызовов. Он изначально пустой; строки добавляются настоящими запусками.

## Проверки без API

Тесты используют локальную заглушку клиента и не обращаются к серверу:

```bash
uv run pytest -q
```

Проверяются как минимум три обязательных ситуации: чужой ID, повтор одного ID и `no_match`. Также проверяются успешная выдача и наличие тегов `<каталог>` и `<запрос>` в отправляемом сообщении.

Локальный результат тестов в этой сборке:

```text
.....                                                                    [100%]
5 passed
```

## Локальная модель Qwen

Установи и запусти Ollama, затем скачай модель:

```bash
ollama pull qwen3.5:4b
```

В `.env` укажи:

```env
OPENAI_API_KEY=ollama
OPENAI_BASE_URL=http://127.0.0.1:11434/v1
OPENAI_MODEL=qwen3.5:4b
OPENAI_REASONING_EFFORT=none
```

`reasoning_effort="none"` передаётся в запрос, когда задан `OPENAI_REASONING_EFFORT`. Для Qwen это отключает рассуждения и делает пробный запуск на CPU существенно быстрее. После локального тестирования можно вернуть параметры облачного API.

## Эксперимент: память модели без каталога

Запусти:

```bash
uv run memory_probe.py
```

Скрипт выбирает 10 фильмов из `films.json`, но отправляет модели только их ID и названия. Год и длительность в запрос не попадают. Ответ модели сравнивается с данными каталога, печатаются расхождения по годам и минутам, а подробный результат сохраняется в `memory_probe_result.json`.

**Результат эксперимента:** пока не заполнен. Его нужно получить запуском скрипта с рабочей моделью; заранее подставлять ожидаемое число ошибок нельзя. После запуска внеси в этот раздел фактические числа из терминала и JSON-файла.

## Проверка 15 запросов и журнал

```bash
uv run check.py
uv run show.py
```

`check.py` выполняет 15 реальных запросов и сверяет ответы с `expect`. Для каждого запроса с `must` должен быть выбран хотя бы один ожидаемый ID и не должно быть ID из `forbid`. Для `no_match` ожидается соответствующий исход. Все вызовы дописываются в `calls.jsonl`.

**Результат `check.py`:** ожидает первого запуска с настроенным API. Вставь сюда фактический итоговый блок терминала после запуска.

**Результат `show.py`:** ожидает первого запуска с настроенным API. Вставь сюда фактический вывод после запуска `check.py`.

Не записывай в README придуманные числа: проверяющий сверяет статистику с `calls.jsonl`.

## Источники данных

Для международной части использован `TMDb 5000 Movies Dataset` (`tmdb_5000_movies.csv`), а индивидуальная ссылка на карточку TMDb сохранена в `source`. Для казахстанских фильмов использованы каталоги UCL, IFFR, Казахфильм и фестивальные каталоги. Полный список источников и правила преобразования находятся в `README_films_sources.md` и поле `source` каждой записи `films.json`.

Жанры, страны и языки приведены к русским названиям. Страна записана как `Казахстан`. `description` — краткий русскоязычный синопсис; это единственное поле, которое допускается формулировать с помощью модели.

## Ответы на вопросы по проверке

1. **Почему сверяется ID, а не название?** ID однозначно связывает ответ модели с конкретной записью каталога. Название может быть переведено, написано с ошибкой или совпасть у разных фильмов. Число расхождений памяти модели нужно взять из `memory_probe_result.json` после запуска `memory_probe.py` и записать здесь: **пока не измерено**.
2. **Что произойдёт при чужом `film_id`?** `pick()` сравнит все ID с переданным каталогом, вернёт исход `invalid`, пустой список ID и запишет чужие значения в `rejected` в `calls.jsonl`. Пользователь не увидит такой фильм. Проверка находится в `kino.py`, функция `pick()`.
3. **Чем «модель ответила без ошибки» отличается от правильного подбора?** `ok` означает, что структура ответа корректна, ID известны, нет повторов и количество фильмов допустимо. Это ещё не доказывает, что фильм соответствует пожеланию. Соответствие смыслу проверяется через ожидания `must` и `forbid` в `check.py`.
4. **Какое решение без ML и чего ему не хватает?** Точный поиск по жанрам, годам, языкам, длительности и словам в описании. Он не понимает перефразирование, настроение и семантическое сходство сюжетов, поэтому может не найти подходящее кино при запросе своими словами.

## Журнал и безопасность

`calls.jsonl` хранит время, модель, текст запроса вместе со списком ID каталога, исход и длительность вызова. При наличии данных usage сохраняются токены и расчётная стоимость. Сам каталог целиком в журнал не копируется. API-ключ хранится только в `.env`; файл исключён через `.gitignore` и не должен попадать в Git.
